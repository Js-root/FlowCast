========================================================
  FLOWCAST — Predict traffic before it happens
========================================================

AI-Powered Micro-Event Traffic Disruption Predictor.
The Pre-Traffic Intelligence Layer for smart cities.

FlowCast fuses real-time social-media event signals with GPS
anomalies to forecast Delhi traffic jams 15–30 minutes BEFORE
congestion forms.

(flow + forecast)


--------------------------------------------------------
  EXECUTIVE SUMMARY
--------------------------------------------------------

THE PROBLEM
Delhi's roads gridlock within minutes from protests, VIP convoys,
processions, road cave-ins, floods, and accidents. Navigation apps
rely on vehicle-speed data — so they only see congestion AFTER it
has already formed.

THE SOLUTION
FlowCast fuses real-time social-media signals, official updates,
and GPS anomalies to forecast disruptions 15–30 minutes before
congestion forms — so commuters and fleets can reroute early.

THE VISION
Become the AI prediction layer under every navigation platform,
logistics fleet, and smart-city traffic system.


--------------------------------------------------------
  ELEVATOR PITCH (30 seconds)
--------------------------------------------------------

Imagine knowing about a traffic jam before it exists. FlowCast
listens to geo-tagged social posts, official traffic handles, and
live GPS. Using multilingual event detection and spatio-temporal
prediction, it forecasts disruptions from protests, VIP movement,
accidents, or road failures 15–30 minutes ahead — helping
commuters, emergency responders, and logistics fleets avoid delays
before they happen.

--------------------------------------------------------
  WHAT MAKES IT DIFFERENT
--------------------------------------------------------

Prediction, not reaction. FlowCast combines:
  - Multilingual (Hinglish / Hindi) event detection from posts
  - Social-media intelligence as an early signal
  - GPS flow-anomaly correlation
  - Spatial impact-radius forecasting (Now, +15, +30 minutes)

The edge: fusing UNSTRUCTURED social signals with STRUCTURED GPS
data to warn BEFORE the speed data even moves.


--------------------------------------------------------
  FEATURE PLAN — PHASE 1 (build fast, ship, win)
--------------------------------------------------------

Rule: Phase 1 holds only features that are BOTH cheap to build AND
win points on stage. Anything needing real infrastructure, paid
data, or ML training moves to Phase 2.

CORE PIPELINE
  - Delhi map (dark theme) with 3 scripted events
    (Connaught Place / ITO / India Gate)
  - Event classification — keyword rules + optional AI (the
    "AI" layer, Hinglish-aware)
  - Location lookup from a Delhi landmark gazetteer
  - Warning -> Confirmed cross-validation
    (1 signal = yellow, 2 signals = red) — the live answer to
    "what if the tweet is fake?"
  - Jam impact-radius with a Now / +15 / +30 minute slider —
    the before/after, the heart of the pitch
  - Naive alternative-route line around the jam
  - "Inject event" buttons — a deterministic, judge-triggerable demo

RICH ADDS (must-have, cheap, high-impact)
  - Live incoming-post feed panel — makes social listening visible
  - Alert toast — "Heavy congestion expected in 18 min"
  - Event popup — type, confidence %, signal count, estimated delay
  - Fake-news demo — a lone unverified post stays yellow, then
    gets debunked (turns the hardest judge question into a feature)
  - Impact stats chip — roads affected, area, estimated vehicles
    (clearly labeled as an estimate)

RICH ADDS (stretch, after the core works)
  - Voice alert (spoken warning) — native, zero dependencies
  - Browser push notification — "the fleet gets pinged"
  - Confidence-scaled visual polish


--------------------------------------------------------
  FEATURE PLAN — PHASE 2 (post-demo roadmap)
--------------------------------------------------------

Harder, time-consuming, or infrastructure-heavy work:
  - Real social feed (Apify / Nitter, then X filtered stream)
  - Live GPS / traffic (TomTom / HERE flow API)

  - Graph-based jam propagation across the road network
  - Persistence + cache (PostGIS + Redis)
  - Streaming pipeline (Kafka / Redpanda)
  - Fleet dashboard with auth + multi-tenant
  - Metro-delay detection, WhatsApp community signals
  - Mobile app, Android widget, Google Maps plugin
  - Multi-city expansion + accuracy backtesting

--------------------------------------------------------
  RISKS & MITIGATION
--------------------------------------------------------

  Noisy / fake social data
    -> Cross-source validation, confidence scoring, and the
       Warning -> Confirmed gate.

  Accurate location extraction
    -> Landmark gazetteer (plus Nominatim later); prioritize
       official handles.

  Real-time processing
    -> Poll now; move to streaming at scale.

  Event verification
    -> GPS correlation + duplicate detection.

SUCCESS METRICS
  Event-detection accuracy, prediction precision, average warning
  time, route accuracy, API latency, user engagement.

--------------------------------------------------------
  JUDGE Q&A PREP
--------------------------------------------------------

  Q: Why AI?
  A: Real-time understanding of multilingual, unstructured social
     data; it warns before GPS speed patterns even move.

  Q: How is this different from Google Maps?
  A: Maps reacts after congestion forms. FlowCast forecasts from
     social signals + GPS anomalies before it begins.

  Q: How do you handle misinformation?
  A: Confidence scores plus GPS / official cross-verification —
     only corroborated events are marked Confirmed.

  Q: How does it scale?
  A: Modular and city-agnostic — onboard a new city by adding its
     local data sources and map layers.

  Q: "Show me the Kafka / big ML model."
  A: Honest answer — the MVP runs a lean, zero-cost stack. The
     heavy infrastructure is the funded production roadmap. We
     built the demo, not the datacenter.
